# 手机记录 App（听歌日记 / 感想 / 照片）需求分析

> 状态：~~需求定稿（2026-02）~~ **已被 [09-standalone-android-app.md](09-standalone-android-app.md) 取代**（2026-09：PWA「记一笔」下线，改为独立 Android 原生 App「Lordestar」，仅本人使用；本文保留作历史需求参考）。
> 决策背景：现有站点为纯静态（Astro + Markdown + Decap CMS），本需求要求引入服务器与数据库，把内容从 Git 仓库迁入数据库，并新增"手机端记录 → 网站展示"闭环。已确认使用 Cloudflare 免费栈（Pages Functions + D1 + R2 + Access），**月成本 ¥0**。

## 1. 产品目标

在手机上有一个 App（PWA，可添加到主屏幕），支持三种记录方式；提交后个人网站实时展示，形成个人内容闭环：

1. **记歌**：粘贴网易云音乐分享链接/文本 → 自动解析歌曲 → 网站首页"最近在听"版面更新，并记入听歌日记；
2. **记感想**：输入一段文字 → 提交 → 网站"想法"列表出现一条新文章（合并进现有想法列表）；
3. **记照片**：拍照/选图 + 配文 → 上传 → 公开后展示在网站上。

**单人使用**：只有站长本人能发布、能看私有内容；网站只展示本人内容；登录与站长邮箱绑定。

## 2. 已确认的关键决策

| 决策点             | 结论                                                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| App 形态           | **PWA**（manifest + service worker，加到主屏幕全屏运行），先不做出原生 App                                                                      |
| "最近在听"版面     | 首页固定区块，展示**最新一首**公开听歌记录；卡片采用 **"Holo" 全息卡**形态（灰白卡片主体 + 专辑封面 + 歌名/歌手 + 指针/倾斜跟随的全息箔片效果） |
| 链接解析范围       | 仅**网易云单曲**分享链接（先做最小可用，专辑/歌单/其他平台列入后续）                                                                            |
| 解析失败兜底       | **允许手动补填**歌名/歌手，不让记录卡住                                                                                                         |
| 感想与现有想法关系 | **合并进现有想法列表**（复用现有列表/详情页，数据迁到 D1 后由 App 直接新增记录）                                                                |
| 隐私默认           | **默认私有**，每条可勾选"公开"；首页/列表只展示公开内容                                                                                         |
| 鉴权               | **Cloudflare Access 邮箱验证码**（免费 50 用户，本需求只用 1 个），绑定站长邮箱                                                                 |

## 3. 用户故事与场景

### 3.1 记歌（听歌日记）

- 用户在网易云 App 点分享 → 复制分享文本，如：
  `分享王菲的单曲《旋木》: https://163cn.tv/bdjTiUah (来自@网易云音乐)`
- 在 lordestar App 粘贴 → 点"记录"。
- 系统自动解析出：歌名《旋木》、歌手 王菲、封面图、网易云歌曲链接。
- 记录成功提示；可勾选"公开"（默认私有）、可附加一句话备注。
- 网站首页"最近在听"立即更新为这首歌；听歌日记页按时间倒序展示全部记录（含私有，仅本人登录可见）。

### 3.2 记感想

- 用户输入一段文字（如"今天循环了一下午的磁带感。"）→ 可选勾选"公开"。
- 公开后：网站"想法"列表出现一条新文章（标题自动取正文前 20 字，可手动修改），详情页可阅读。

### 3.3 记照片

- 用户拍照/从相册选图 → 配文（可选）→ 提交。
- 图片自动压缩后上传 R2；公开后出现在想法列表（带图卡片）与详情页。
- 手机端支持多图（先支持 1~4 张）。

### 3.4 查看与编辑

- App 内可查看"我的记录"列表（听歌/文字/照片，含私有），支持编辑（改文案/公开开关）与删除。
- 网站访客只能看到公开内容。

## 4. 功能需求

### 4.1 网易云链接解析（核心）

**输入**：分享文本（含短链 `https://163cn.tv/xxx`）或裸链接。
**解析流水线（服务端，Pages Function 内完成）**：

1. 正则从文本中提取 URL（`https?://[\w./?#=-]+`）；
2. 跟随 302 重定向解析短链，得到真实页面地址，提取歌曲 id：
   - `https://music.163.com/song?id=1135369`（query 形式）
   - `https://music.163.com/#/song?id=1135369`（hash 形式）
3. 用歌曲 id 请求网易云公开接口取元数据（歌名/歌手/专辑/封面 URL）：
   - 首选 `https://music.163.com/api/song/detail?id={id}&ids=[{id}]`（免登录公开接口）；
4. 封面图下载到 R2（key：`diary/song-covers/{id}.jpg`），避免外链失效/防盗链；下载失败则回退直接用 126.net 外链；
5. 校验通过 → 写入 `diary` 表（kind='song'）。

**兜底**：步骤 2/3 任一失败 → 从分享文本直接解析《歌名》与"分享{歌手}的单曲"句式；仍失败 → App 弹出手动补填表单（歌名必填，歌手/封面可空）。

**限制**：

- 非单曲链接（专辑/歌单/电台/用户页）→ 明确提示"暂只支持单曲分享"；
- 未识别的分享文本 → 引导手动补填。

### 4.2 "最近在听"版面（首页）

**形态（已确认，参考 "Holo" 全息卡）**：首页"最近在听"是一张可交互的全息卡片，作为 React 组件以 `client:load` 挂载：

- **卡片主体**：灰白色打印面（固定颜色，不随材质变化）——替换原版 Holo 卡的粉红色；
- **图片位**：**专辑封面**——替换原版的人物照片；封面来自 R2（或 126.net 外链），作为卡片角落的"照片瓦片"，保留双色调/翻转的材质感；
- **文字**：**歌曲信息**——歌名（主标题）+ 歌手（副标题），替换原版的姓名/关系文案；
- **保留的效果**：3D 倾斜跟随（指针 + 手机陀螺仪）、多层全息箔片（不同角度/速度的渐变层互相干涉产生油彩质感）、高光与眩光、边缘受光、离面时的材质浮现；
- **移除/简化的部分**：爱心装饰、原版的人物信息文案；"查看日记"入口保留（作为卡片下方的小链接或独立按钮）。

**数据来源**：`diary` 表 `kind='song' AND public=1` 按 `created_at DESC` 取 1 条。
**实现方式**：首页 `HomePage.astro` 在 SSR 下查询 D1 → 把 `{title, artist, cover, song_url}` 作为 props 传给 `<NowListeningCard client:load />`；无公开记录时不渲染该区块。
**交互**：卡片随指针/手机倾斜转动；点击 → 网易云原链接（新标签页）。
**实时性**：App 提交后下次刷新首页即更新（不要求推送/长轮询）。

**技术适配说明**（从原版 Next.js 组件移植到本项目）：

- `engine.ts`（数学/材质引擎）与框架无关，可直接复用，仅需替换 `mediaUrl()` 引用（本项目封面 URL 直接来自数据库）；
- `HoloCard.tsx` 需要从 Next.js 适配到 Astro 的 React 岛：去掉 `view-transition` 依赖、改为 props 传入歌曲数据；
- 原版 CSS（`holo.css`）未提供（用户侧仅有 `engine.ts` 与 `HoloCard.tsx` 两段源码），由我们按引擎定义的 CSS 变量契约（`--rx/--ry/--l1..3-*/--tile-*/--gx/--gy/--reveal-*` 等）**自写样式**，全息效果尽力还原；
- 卡片实现排期：**M1 迁移完成之后**再落地（与数据库接入一起做，避免返工）。

### 4.3 想法列表合并

- 现有 `posts` 表（迁移自 `src/content/posts/`）与 App 提交的公开记录合并展示：
  - `kind='text'`：标题 + 正文摘要（截断）→ 复用 PostCard 风格卡片；
  - `kind='photo'`：标题（可选）+ 配文 + 图片缩略图 → 带图卡片；
- 排序：`created_at DESC` 统一倒序；分页（先 20 条/页）。
- 详情：text/photo 记录有独立详情页 `/thoughts/entry/{id}/`（或与 posts 共用路由，实现时定）。

### 4.4 记录（diary）数据模型

```sql
CREATE TABLE diary (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT NOT NULL CHECK (kind IN ('song', 'text', 'photo')),
  title TEXT DEFAULT '',           -- 歌名 / 感想标题 / 照片标题
  artist TEXT DEFAULT '',          -- 歌手（song）
  album TEXT DEFAULT '',           -- 专辑（song，可选）
  cover TEXT DEFAULT '',           -- 封面（R2 key 或外链，song）
  ncm_id INTEGER,                  -- 网易云歌曲 id（song，可选）
  song_url TEXT DEFAULT '',        -- 网易云原链接（song）
  note TEXT DEFAULT '',            -- 配文 / 感想正文
  images TEXT DEFAULT '[]',        -- 图片 R2 key 列表（JSON，photo）
  public INTEGER NOT NULL DEFAULT 0,  -- 0=私有 1=公开
  created_at TEXT NOT NULL,
  updated_at TEXT
);
CREATE INDEX idx_diary_song_public ON diary(kind, public, created_at DESC);
```

- `posts` 表在迁移时新增可选字段 `images TEXT DEFAULT '[]'`（供照片型想法使用）。
- 单用户系统：不设 owner 字段；鉴权只控制"谁能写/谁能看私有内容"。

### 4.5 App（PWA）功能清单

| 页面                    | 功能                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------- |
| 记录页 `/app/new`       | 三种输入 Tab（听歌 / 感想 / 照片）；粘贴识别、手动补填表单、拍照/相册、公开开关、提交 |
| 我的记录 `/app/records` | 全部记录列表（含私有），编辑 / 删除                                                   |
| 听歌日记 `/app/diary`   | 仅 song 记录的时间线视图（公开版在网站端 `/diary/`）                                  |
| 登录                    | Cloudflare Access 邮箱验证码，一次登录，会话保持                                      |

**PWA**：manifest（图标、主题色、全屏）、service worker（静态资源缓存、离线可打开记录页）、"添加到主屏幕"。

### 4.6 鉴权（Cloudflare Access）

- 保护范围：`/app/*`、`/admin/*`、所有写接口（POST/PUT/DELETE）。
- 登录方式：站长邮箱接收一次性验证码；Access 免费额度 50 用户内（实际 1 用户）。
- 读接口区分：公开数据无需登录；私有数据（含个人记录）需登录后返回。
- 现有 `functions/admin/oauth`（GitHub OAuth）退役，Decap CMS 一并移除（内容已迁 D1）。

### 4.7 接口设计（同时为未来原生 App 预留）

| 接口               | 方法           | 说明                                                      |
| ------------------ | -------------- | --------------------------------------------------------- |
| `/api/diary`       | GET            | 列表（登录见全部；访客仅公开）                            |
| `/api/diary`       | POST           | 新增记录（登录）                                          |
| `/api/diary/:id`   | GET/PUT/DELETE | 详情 / 编辑 / 删除（登录，私有内容仅本人）                |
| `/api/ncm/resolve` | POST           | 提交分享文本/链接，返回解析结果（登录）                   |
| `/api/upload`      | POST           | 上传图片到 R2，返回 key（登录，≤4 张/次，压缩后 ≤2MB/张） |
| `/media/*`         | GET            | R2 图片公开代理访问                                       |

## 8. 开放问题（实现前确认）

1. 感想/照片记录详情页的路由形态：与现有 posts 共用 `/thoughts/:slug/`，还是独立 `/thoughts/entry/:id/`？
2. 公开照片是否同步进"关于页照片墙"（`public/photos/` 目前是构建时静态扫描）？
3. 想法列表是否需要对 diary 记录做分页（现有 posts 列表无分页）？
4. "最近在听"卡片：原版 CSS 不可得，样式由项目自写（见 4.2）；实现排在 M1 迁移之后。
